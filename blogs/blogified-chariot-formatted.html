Upgrading My Blog

Barebones tool to streamline the conversion

As a belated celebration of my 1 year blogging journey I decided to make it EVEN easier to put my thoughts out into the internet ether. Specifically I looked into automating the process of converting my blogs into HTML pages. While I have done this conversion with a few blogs (example), the process was nothing short of an ordeal and likely took up just as much time as writing the text part of the blog. At the time the workflow involved manually editing the raw exported HTML file Google Docs provides and slowly adding in custom images/blurs/etc. Since I rarely need that level of customization I ended up defaulting back to publishing PDF files as its consistency in format rendering combined with ease of use made it nearly uncontested in my eyes.

That was the status quo until I saw a project at work that aimed to automate this process (with some caveats) and after some tinkering with the concept I have a version I’m mostly happy with.

Disclaimer: I did use ChatGPT (not an #ad) to create this tool but it did allow me to complete the whole MVP in 90 minutes so I don’t even need to spend my day off debugging!

New Workflow

As a reminder for how my blog creation process normally works it’s like this:

  1. Write the blog in Google Docs
  2. Stylize and format the Google Doc
  3. Export the doc as-is as a PDF
  4. Update a custom JSON metadata file
  5. Add the blog to the blog folder
  6. Publish via Git commit

Thanks to my initial setup 14 months ago this process automatically populates my homepage with the blog and the overhead is generally less than a minute. So when my goal is to replace the PDF file with an HTML file the solution has some additional requirements:

  1. It must take under a minute to convert from Google Doc to a blog-ready state
  2. There must be a consistent and free tool I can always use to convert the file
  3. The final file must be easy to manage

Luckily the solution at hand can accommodate for all 3 and relies on Google Doc’s export process hardcoding a lot of the styling and tags in a formulaic way. Basically we do the following:

  1. Export the written blog as a zipped HTML file
  2. Drop the zip into the tool
  3. A minified implementation of JSZip on the repo unpacks the contents
  4. We parse the HTML and begin reading the DOM
  5. Via Query Selectors we extract and reconstruct the blog into proper HTML nesting and structure
  6. Once the DOM is rebuilt we reapply CSS (italics, bolds, margins)
  7. Finally we perform last minute cleanups to ensure Google Doc artifacts are all removed before the file is downloaded

Now the workflow would work like this:

  1. Write the blog in Google Docs
  2. Stylize the Google Doc
  3. Export the doc as a zipped HTML file
  4. Convert the zip into a converted HTML file
  5. Update a custom JSON metadata file
  6. Add the blog-converted HTML file to the blog folder
  7. Publish via Git commit

For additional customization (eg. blurs, embeds, interactive elements) I can now easily add them before step 6 and since our reconstructed HTML file removes most of the Google Doc bloat the process should be much better than it used to be.

Final Thoughts

While it does work and is fast I do have some gripes that I’ll probably address whenever I feel like it:

  1. We don’t have size checks for the uncompressed zip file
  2. We assume the HTML file is safe to read
  3. Images are stored as data blobs and are its original size
  4. Videos and other larger media files might be impossible to store as-is
  5. The tool is currently disjointed from the metadata generator when ideally they’re placed together

But even with the gripes I’m very pleased with the enhancement since this month could have quite a few interesting blog worthy events…
